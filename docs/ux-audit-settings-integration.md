## 3. Verificación Explícita de las Hipótesis de Fase 0

### `/settings` (6/6 hipótesis confirmadas)
1. **Claves `cf_pub_*`:** **Confirmado hueco (SET-08).** El backend ya soporta `is_publishable`, `allowed_origins`, `allowed_agents`, `daily_quota_requests` y `last_used_at`, pero `/settings` solo permite crear `cf_live_*` genéricas con `allowed_projects: ["*"]` y no muestra `last_used_at` ni cuota usada/diaria.
2. **Egreso `local`/`cloud` y rótulo `"CLI Local"`:** **Confirmado engañoso (SET-01).** La pestaña dice `"CLI Local"` y las tarjetas muestran `local_cli`, contradiciendo `BR-21` (donde `agy`/`claude`/`gemini`/`codex`/`opencode`/`aider` tienen egreso `cloud`, bloqueado en `sovereign_only` y agentes `public`).
3. **Tabla `settings`:** **Confirmado incompleto (SET-06).** Faltan controles y persistencia en UI para `ollama_url`, `min_grounding_score`, `enable_dlp_redaction` y `enable_extractive_fallback`, además de aviso de reindexado al cambiar `embedding_model`.
4. **Auditoría y DLQ:** **Confirmados bugs/huecos (SET-09, SET-10).** Falta botón `GET /api/v1/audit-logs/verify`; la DLQ nunca muestra elementos por bug de casing (`'DEAD_LETTER'` vs `'dead_letter'`), no muestra `error_detail` y hardcodea `?project=default`.
5. **`AUTH_MODE`, bind no-loopback, Salud y `/metrics`:** **Confirmado ausente (SET-11).** Ninguno aparece en `/settings`.
6. **Separación Workspace vs Proyecto:** **Confirmado (SET-12).** Webhooks, Export/Import y Miembros no tienen UI y `/settings` mezcla alcance global y de proyecto. Además se detectaron 4 métodos JS huérfanos y motores BD/Storage ficticios en Tab 3 (**SET-07**).

### `/docs/integration-guide` (4/4 hipótesis confirmadas)
1. **Cobertura incompleta:** **Confirmado (INT-02, INT-03, INT-04).** Faltan Gateway OpenAI `/v1/*` (y límites/errores HTTP 400), Webhooks HMAC + timestamp anti-replay, Feedback/Knowledge Gaps, `/metrics` y autenticación por modo.
2. **Snippets con contexto real y prueba en vivo:** **Confirmado (INT-01, INT-07).** Faltan selectores de proyecto/agente, los botones Python/JS/cURL no actualizan el `<pre>` visible y no existe `"Probar conexión"` en vivo.
3. **Widget solo con agentes `public`:** **Confirmado (INT-05).** El snippet actual omite `data-agent` y `data-publishable-key` y no valida ni explica `visibility="public"`.
4. **MCP por cliente + Postman v2.1:** **Confirmado (INT-06, INT-08).** MCP omite header `X-API-Key` para `enterprise_rbac` y pestaña de Claude Desktop; `PostmanCollectionBuilder` hardcodea `Admin123!` y `arch_retries.md`, apunta a `/mcp/` y omite todos los endpoints nuevos de Bloques 1–4.
